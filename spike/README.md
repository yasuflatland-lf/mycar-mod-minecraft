# 走行コア スパイク（使い捨て）

このディレクトリのコードは検証専用です。本実装には流用しません。ここで分かったことと決まった要件は、走行コアの仕様書に引き継ぎます。

## 検証した問い

1. 乗車中に PC とスマホで `getMovementVector()` が取れるか。スマホの左右入力はアナログ値か
2. スクリプト方式（案 1）で走らせたとき、運転者視点のカメラは滑らかか。同乗者からはどう見えるか
3. エンジンの摩擦・重力がスクリプトの速度を打ち消すか。段差を越えられるか
4. 馬方式（案 2）と比べて、操作感に差があるか

比較用の 2 台:

| エンティティ | 方式 | 見た目 |
|---|---|---|
| `spike:car_script` | 案 1: 毎 tick スクリプトで速度を計算し `applyImpulse` で与える | カーキの SUV |
| `spike:car_horse` | 案 2: 馬と同じ `minecraft:input_ground_controlled` | 青い SUV |

## 動かし方

```sh
cd spike/server
docker compose up -d
docker logs -f server-bds-1                                       # [SPIKE] で始まる行が計測結果
docker exec server-bds-1 send-command op <プレイヤー名>            # コマンドを使えるようにする
docker exec server-bds-1 send-command scriptevent spike:autotest  # 自動計測
```

- 接続先: この Mac の LAN IP、ポート 19132（「サーバー」タブ →「サーバーを追加」）
- 車を出す: `/summon spike:car_script`、`/summon spike:car_horse`
- 乗る: 右クリック（スマホはタップして「Drive」）。降りる: スニーク
- 操作: 前後でアクセルとバック、左右でハンドル、ジャンプでハンドブレーキ
- 運転中はアクションバーに入力値・指令速度・実速度・横滑り角が出る。1 秒ごとにサーバーログにも出る

BDS の初期設定 `transport=nethernet` は待ち受けポートが毎回ランダムで、Docker のポート転送が届かない。`compose.yaml` で `TRANSPORT: raknet` にしている。

## 自動計測の結果（BDS 1.26.52 / Docker）

| テスト | 内容 | 結果 |
|---|---|---|
| T1 | 直進加速 → 1 段の段差 → 惰性 | 39 tick で最高速度の 95%。段差を越えた。惰性 22.76 ブロック |
| T2 | 全開旋回（通常 / ハンドブレーキ） | 横滑り角 13.8° / 52.4° |
| T3 | 前方の牛に突っ込む | 12 ダメージで倒れ、約 4 ブロック押し出された（死因 `entityAttack`） |
| T4 | 高さ 4 の壁に斜め 20° で突っ込む | 壁の手前で止まった。壁沿いの速度は最大 0.32 |
| T5 | 2 段の段差に正面から近づく | 2.5 ブロック手前で跳び、段の上に乗った |
| T6 | 2 段の段差に斜め 30° で近づく | 車の端の先読みで跳び、横ずれ 0.00 で乗った |

## 分かったこと

- **摩擦の補正が必要:** エンジンの地面摩擦で速度が 1 tick ごとに約 0.69 倍になり、何もしないと指令の 40% しか出ない。前 tick の結果から減衰率を推定して上乗せすれば、指令どおりに走る
- **壁と摩擦の区別が必要:** 壁に当たった減速を摩擦と誤認すると補正が暴走し、壁沿いに全速力で滑る。x・z の軸ごとに「与えた速度がほぼ消えたか」で衝突を判定し、衝突中は内部速度を実速度まで落とす
- **段差:** 1 段は `minecraft:variable_max_auto_step` に任せられる。2 段は上限を上げても越えられないので、スクリプトで前方を先読みして跳ばせる。斜めに近づくと車の角が先に当たるため、先読みは中心線と左右の端の 3 本で行う
- **衝突ダメージ:** 前方の長方形（見た目の車体の前端 + 相手の体の半分の幅）で判定し、`applyDamage` と `applyKnockback` を与える。サーバー側で判定するので、高速時は見た目より最大 1 tick 分手前で当たることがある
- **自分のダメージ:** 車に `minecraft:damage_sensor` を付けると、壁への激突でも 10 ブロックの落下でも、運転者・車ともダメージを受けない
- **向き:** `/summon` した車は向きが固定なので、乗車時に車の向きを運転者の視線に合わせる。運転席に `lock_rider_rotation: 90` を付けると、曲がったときにカメラが車についてくる
- **モデルの向き:** Bedrock ではエンティティの正面がモデルの -z 側。前方 +z で作ったモデルは 180° 回して書き出す
- **テストの注意:** `dimension.spawnEntity` で出したモブは、プレイヤーから離れていると 1 tick で削除される（`summon` は削除されない）。`fill` は 1 回 32,768 ブロックまで

## 手動テストの結果（スマホ）

| 項目 | 結果 |
|---|---|
| 乗車中の入力 | 取れる。左右はアナログ値（`x=0.09`、`0.81` など） |
| 1 本ジョイスティック | ハンドルを大きく切るとアクセルが下がる（`x=0.90` で `y=0.48`）。本設計で補正を決める |
| カメラの追従 | 曲がると車についてくる |
| 2 段の段差 | 正面からも斜めからも自然に乗り越えられる |
| 衝突ダメージ | 豚・牛にダメージが入り、押しのけられる |
| 自分のダメージ | 壁への激突でも落下でもハートは減らない |
| 案 2（馬方式）の曲がり方 | 左右入力で真横に滑る（カニ歩き）。車らしく曲がれない |

## 決まった要件（仕様書に引き継ぐ）

- 走行: アーケード寄りの加速・慣性・横滑り。ジャンプでハンドブレーキ
- 段差: 2 段まで越えられる。3 段以上は壁として止まる
- 衝突: 自分（運転者・同乗者）と車は衝突・落下でダメージを受けない。ぶつかった相手は速度に応じたダメージを受け、押しのけられる
- 車体: 4 ドアのオフロード SUV、カーキ、右ハンドル、4 席。車内に座る
- 外装: 丸目ヘッドライト、縦スロットのグリル（8 本。7 本は Jeep の登録商標なので避ける）、ウィンカー、フォグランプ、サイドミラー、背面のスペアタイヤ、右後ろのマフラー
- 内装: 丸いハンドル、メーター 2 つ、シフトレバー、ルームミラー
- 演出: タイヤの回転、乗車中の排気ガス
- 未実装: 降りるときにドアが開いて音が鳴る（ドアを独立したボーン `door_fl` などにする）
