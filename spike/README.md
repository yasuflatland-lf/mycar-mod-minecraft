# 走行コア スパイク（使い捨て）

このディレクトリのコードは検証専用です。本実装には流用しません。

## 検証する問い

1. 乗車中に PC とスマホで `getMovementVector()` が取れるか。スマホの左右入力はアナログ値か
2. スクリプト方式（案 1、赤い車）で走らせたとき、運転者視点のカメラは滑らかか。同乗者からはどう見えるか
3. エンジンの摩擦・重力がスクリプトの速度を打ち消すか。1 ブロックの段差を越えられるか
4. 馬方式（案 2、青い車）と比べて、操作の軽さに差があるか

## サーバー

```sh
cd spike/server
docker compose up -d
docker logs -f server-bds-1        # [SPIKE] で始まる行が計測結果
docker attach server-bds-1         # コンソール（抜けるときは Ctrl-P Ctrl-Q）
```

自動計測（問い 3）：コンソールで `scriptevent spike:autotest` を実行する。

## 手動テスト（問い 1・2・4）

接続先: この Mac の LAN IP、ポート 19132（「サーバー」タブ →「サーバーを追加」）。

1. クリエイティブのインベントリから「赤い車」と「青い車」のスポーンエッグを出して置く
2. 車を右クリック（スマホはタップ）で乗る。スニークで降りる
3. 画面下のアクションバーで、`in x= y=` が操作に応じて変わるかを見る
   - スマホのジョイスティックを少しだけ傾けたとき、0 と ±1 以外の値が出ればアナログ
   - ジャンプで `hb=1` になるか（ハンドブレーキ）
4. 赤い車で直進、旋回、ジャンプ押しながら旋回（横滑り）を試す。カメラのガタつきを 5 段階で評価する
5. もう 1 人が後部座席（2 人目に乗る）に乗り、運転中の車の見え方を評価する
6. 青い車で同じコースを走り、操作の軽さを比べる

## 自動計測の結果（2026-10-10、BDS 1.26.52 / Docker）

| 項目 | 摩擦補正なし | 摩擦補正あり |
|---|---|---|
| 実速度／指令速度 | 0.40 | 1.00（39 tick で 95% 到達、推定摩擦 0.688） |
| 1 ブロックの段差 | 到達せず | 越えた（`minecraft:variable_max_auto_step` が有効） |
| 惰性の距離 | 9.15（エンジン摩擦任せ） | 22.76（スクリプトの drag どおり） |
| 横滑り角（通常 / ハンドブレーキ） | 5.3° / 11.0°（失速） | 9.1° / 40.6°（速度維持） |
| tick 間隔（安定後） | 43〜57ms | 48〜52ms |

分かったこと:

- エンジンの地面摩擦（1 tick あたり約 0.69 倍）がスクリプトの速度を打ち消す。前 tick の結果から減衰率を推定して上乗せすれば、指令どおりに走る
- 段差の乗り越えはエンジンに任せられる
- 未解決: ハンドブレーキ中に速度が最高速度を超える（0.757）。調整の範囲

## 衝突ダメージ（2026-10-10 追加）

要件: 自分（運転者・同乗者）と車はダメージを受けない。ぶつかった相手は速度に応じたダメージを受け、押しのけられる。

- 車: `minecraft:damage_sensor` で全ダメージ無効（エンティティ定義の変更なので、サーバー再起動後に反映）
- 相手: 車の前方の長方形（前 1.6、横 ±1.1）にいる相手へ `applyDamage`（最高速度で 12）と `applyKnockback`
- 運転者・同乗者・車が何かのダメージを受けたら `self-hurt` としてログに出す

自動計測 T3 の結果: 速度 0.6 で牛に当たり、12 ダメージで倒れ、4.12 ブロック押し出された（死因 `entityAttack`）。

注意: `dimension.spawnEntity` で出したモブは、プレイヤーから離れていると 1 tick で削除される。テストでは `summon` コマンドで出している。

## 手動テストの結果

| 項目 | 結果 |
|---|---|
| 乗車中の入力（スマホ） | 取れる。左右はアナログ値（`x=0.09`、`0.81` など） |
| スマホの 1 本ジョイスティック | ハンドルを大きく切るとアクセルが下がる（`x=0.90` で `y=0.48`）。本設計で補正を決める |
| 赤い車の向き | 当初は車の向きと視線がずれて前後が逆に感じた。乗車時に車の向きを視線へ合わせ、運転席に `lock_rider_rotation: 90` を付けて解消 |
| 赤い車のカメラ追従 | 曲がると車についてくる |
| 青い車（案 2）の曲がり方 | 左右入力で真横に滑る（カニ歩き）。車らしい旋回にならない |
